# 시나리오 작성 가이드

이 폴더의 `*.json` 파일 하나가 시나리오 하나다. 서버는 시작할 때 이 폴더를 읽어서 자동으로 목록에 올린다.
**새 시나리오는 `fire_office.json` 을 복사해서 내용만 바꾸는 게 가장 쉽다.**

시나리오는 하네스의 "재료"다. AI는 이 문서를 보고 캐릭터 연기와 판정을 하고, 서버는 이 문서의 규칙으로 단계를 진행한다.
→ 문서가 구체적일수록 AI가 덜 헤매고, 정답 기준이 정확할수록 교육 효과가 생긴다.

## 전체 구조

| 필드 | 뜻 | 예시 |
|---|---|---|
| `id` | 영어 소문자·밑줄, 파일 이름과 같게 | `earthquake_school` |
| `title`, `summary`, `category` | 목록 카드에 보이는 정보 | "학교 지진 대응", "지진" |
| `role_doc` | **롤 문서**: 장소, 상황, 캐릭터가 지킬 규칙 | |
| `characters` | 등장인물 (이름, 역할, 성격, 말투) — 실존 인물 이름 금지 | |
| `characters[].introduction`, `quote`, `image` | 브리핑용 인물 소개, 첫인상 대사, 캐릭터 그림 | 선택. 정답을 알려주지 않고 관계·성격·현재 심정을 서술 |
| `max_risk` | 위험도가 이 값 이상이 되면 실패로 끝남 | 6 |
| `stages` | **단계 문서** (아래) | 4~6개 권장 |
| `evaluation` | 리포트 체크 항목. 보통 단계마다 1개 | |
| `sources` | 정답 근거로 쓴 공공기관 자료 | |

## 단계(stage) 한 개

| 필드 | 뜻 | 작성 요령 |
|---|---|---|
| `stage` | 단계 번호 1, 2, 3 … | |
| `title` | 화면에 보이는 단계 이름 | 짧게 |
| `situation` | 이 단계 상황 설명 (내레이션) | 2문장 이내, 눈에 보이는 것 위주 |
| `character_id` | 이 단계에서 말하는 캐릭터 | `characters` 의 id |
| `opening_line` | 캐릭터 첫 대사 | **일부러 틀린 행동을 유도**하면 판단 연습이 된다 (예: "엘리베이터 타자!") |
| `correct_action` | 올바른 행동 | 공공기관 행동요령 근거. 리포트에 정답으로 그대로 보인다 |
| `keywords` | 올바른 행동으로 인정할 표현 | **넉넉히** (동의어, 띄어쓰기 변형). 서버가 이 중 하나는 있어야 통과시킨다 |
| `wrong_keywords` | 위험한 행동 표현 | 가짜 AI 판정에 쓰임 |
| `danger_patterns` | 서버가 위험도 상승을 결정하는 행동 정규식 | 띄어쓰기를 제거하고 동의어를 통일한 입력과 비교. 대상·동사·다양한 어미를 포함하고 질문·금지문도 함께 검증 |
| `danger_defer_patterns` | 현재 단계에서 나중의 조건부 행동으로 분리할 표현 | 선택. 예: 지진 1단계의 "흔들림이 멈추면". 일치하는 문장은 위험 행동 검사에서 제외되므로 좁게 작성 |
| `next_if_correct` | 맞히면 갈 단계 번호 | 마지막 단계는 `null` |
| `if_wrong.narration` | 틀렸을 때 상황 변화 | 끔찍한 묘사 금지 ("기침을 한다" 수준) |
| `if_wrong.risk_delta` | 틀렸을 때 올라가는 위험도 | 1~3 |
| `if_wrong.reply` | 결과 직후의 캐릭터 대사 | 선택 |
| `if_wrong.image` | 기본 위험 행동 결과 컷 | 선택. `frontend/public/scenes/` 기준 경로 |
| `if_wrong.events` | 특정 위험 행동에 대한 별도 결과 | 선택. 항목마다 `patterns`, `narration`, `risk_delta`를 작성. `exclude`, `reply`, `image` 선택 |
| `reactions` | 캐릭터 반응 대사 (correct / wrong / unclear) | AI 오류 시 대신 쓰는 예비 대사이기도 함 |
| `image` | 장면 이미지 파일 이름 | 이미지는 아직 없어도 됨 |
| `image_includes_speaker` | 장면 이미지에 인물이 포함됐는지 여부 | 선택. 참이면 캐릭터 초상화가 겹쳐 표시되지 않음 |
| `action_image` | 서버가 올바른 행동을 확인해 진행할 때 표시할 컷 | 선택. 이미지 경로는 `frontend/public/scenes` 기준 |

단계의 선택 항목 `action_description`은 행동 컷의 대체 텍스트다. `action_alternatives`는 같은 행동 기준에서 별도 컷을 쓸 때 추가한다. 서버는 `evidence`에 지정한 기준의 확인 발언에 `contains`의 단어가 포함되면 해당 `image`, `description`을 사용한다. 시나리오 최상위의 선택 항목 `cleared_image`는 대피 완료 장면이다.

## 진행 규칙 (서버가 강제)

- 필수 행동이 확인되면 다음 단계로 넘어간다. 질문·대화·부분 행동은 위험 행동 횟수를 올리지 않는다.
- 행동 기준의 `hint`는 해당 행동이 남았을 때 등장인물이 말할 단서다. `partial_scene`에 `image`, `situation`을 지정하면 해당 행동을 먼저 완료했을 때 현재 장면 이미지와 설명이 그 시점으로 바뀐다. 이미 확인한 행동은 세션에 저장된다.
- 서버는 문장 순서대로 위험 행동을 검사하며, 같은 문장 안에서는 `if_wrong.events`의 구체적 결과를 `danger_patterns`의 기본 결과보다 먼저 적용한다. 사건이 발생하면 결과를 보여주고 현재 장면에서 이어간다. 위험도가 `max_risk`에 도달하면 그 자리에서 종료한다.
- `wrong_keywords`만 추가하면 서버의 위험도 판정 범위는 넓어지지 않는다. `danger_patterns`도 함께 보강한다. 화재·지진·엘리베이터 전 단계의 위험 표현과 질문·부정·조건부 행동 회귀 사례는 `backend/risk_test.py`에서 확인한다.
- 패턴 수정은 서버 재시작 후 새 플레이에서 확인한다. 이미 시작한 세션은 생성 당시 시나리오 사본을 사용하므로 기존 세션에는 새 패턴이 적용되지 않는다.
- "정답 알려줘", "다음 단계로 넘겨" 같은 말은 서버 필터가 막는다 (단계·위험도 변화 없음).

## 작성 후 확인

```bash
cd backend
python play_test.py          # fire_office 기준 자동 플레이
uvicorn app.main:app --reload   # http://localhost:8000/docs 에서 새 시나리오로 직접 플레이
```
JSON 문법 오류가 있으면 서버가 켜지지 않는다. VS Code에서 열면 빨간 줄로 위치를 알려 준다.

## 운영자 CMS로 편집하기 (2026-11-18 추가)

JSON을 직접 고치는 대신 웹 화면 오른쪽 위 **운영자** 메뉴에서 만들고 고칠 수 있다. (설정: 루트 README "운영자 CMS")
- `status`: `"draft"`(작성 중, 이용자에게 안 보임) / `"published"`(공개). 없으면 공개로 본다.
- `role_doc.world_facts`, 단계별 `facts`: 이용자 질문에 AI가 일관되게 답하기 위한 상황 정보 (위치·인원·사정 등). 대피 요령은 넣지 않는다.
- 저장할 때 서버가 이 문서의 규칙을 검사한다. 오류 메시지가 어떤 칸이 문제인지 알려 준다.
