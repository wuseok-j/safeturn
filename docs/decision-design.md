# 선택이 남는 재난 대응 연습

## 반복 재촉 대사 보강 2026-11-26

AI가 correct를 제안하고 서버가 unclear로 보류할 때, 기존에는 같은 partial_reply로 덮어써 같은 문장이 반복될 수 있었다. 현재는 이번 입력에서 확인한 행동·남은 행동·서버 판정 미리보기를 AI에 전달한다. 정상적인 새 AI 대사는 유지하며, 판정 불일치나 최근3개 캐릭터 대사와 동일한 응답에서는 대화 맥락과 말투를 반영한 안전한 응답을 선택한다. 교사 안내를 따르겠다는 뜻을 먼저 받아 주되 누락된 행동을 수행했다고 꾸며내거나 정답을 나열하지 않는다.

이 처리는 동일 문구 반복을 줄이는 장치이며 모든 의미상 반복이나 미등록 표현 판정을 해결했다고 보장하지 않는다. dialogue_test.py에서 고정대사 재현·AI 대사 보존·중복응답·현재입력 컨텍스트·존댓말을 확인한다. 실제 두 발언 검사는 dialogue_live_check.py로 별도 실행하며 API 비용이 발생한다.

2026-11-17 구현 기준. 경쟁 서비스 전체와의 우위를 검증한 문서가 아니라, 이 프로젝트가 직접 구현하고 시연할 수 있는 특징을 설명한다.

## 핵심 경험

사용자는 위험을 가볍게 보는 동료와 대화하며 행동을 결정한다. 서버는 행동 항목별 근거를 모으고, 미충족 시 다른 사람이 도와야 했다는 상태를 남긴다. 다음 장면과 캐릭터 첫 대사는 이 상태에 따라 바뀐다. 끝난 뒤에는 자신의 발언, 위험도 변화, 항목별 근거와 출처를 비교한다.

## 동작 예시

- 1단계에서 “불이야!”만 말하면 주변 알림 근거만 기록한다. 이어 “119에 신고할게요”라고 하면 두 행동이 충족되어 이동한다.
- “119” 같은 명사, 질문·가정은 실행 의사로 확정하지 않는다. AI가 correct를 제안해도 서버 근거가 없으면 통과하지 않고 성공 대사도 교체한다.
- 3회 동안 필요한 행동을 확인하지 못하면 다른 직원이 경보를 울렸다는 전개가 나온다. 다음 장면도 다른 직원이 경보를 울린 경로로 바뀐다.
- “계단으로 가자. 아니 엘리베이터 같이 타자”처럼 등록된 위험 행동을 함께 제안하면 위험 행동을 우선한다. 해당 단계의 이전 근거는 초기화한다.
- AI 응답 장애·잘못된 반환 형식은 판단 기회를 소진하지 않는다.
- 0개 행동을 통과해도 도움을 받아 건물 밖에 도착할 수 있다. 도착 여부와 행동 충족도는 분리해서 표시한다.

## 파일과 역할

| 파일 | 담당 |
|---|---|
| data/scenarios/fire_office.json | briefing, rubric, danger_patterns, consequence, variants 콘텐츠 |
| backend/app/rules.py | 제한된 행동 패턴 확인 및 위험 패턴 검사 |
| backend/app/harness.py | 상태·근거·위험도·기회·장면·리포트 결정 |
| backend/app/ai.py, gemini.py | Gemini 캐릭터 대사와 판정 제안. 키 없으면 mock |
| backend/app/prompts.py | 필수 행동·서버가 확정한 이전 선택 상태 전달 |
| frontend/src/pages/Report.jsx | 타임라인·발언·충족 항목·출처 표시 |

## 콘텐츠 편집 규칙

`rubric` 한 항목은 확인 가능한 행동 하나다. `patterns`는 그룹 간 AND, 그룹 안 OR인 정규식이다. `exclude`에 해당하면 그 항목은 인정하지 않는다. `source_indices`는 시나리오 sources의 0부터 시작하는 인덱스다. 현재 항목은 행정안전부 행동요령을 연결한다.

`consequence`는 행동 확인 여부를 success/missed로 저장하고 연결 설명을 표시한다. `variants`는 이전 상태에 따라 상황·첫 대사를 바꾼다. 현재 구현은 다섯 단계 안의 상황 변형이며, 자유로운 경로 탐색이나 완전한 분기 트리는 아니다.

콘텐츠 변경 시 정답 표현뿐 아니라 명사만 나열한 표현, 부정, 질문, 위험 행동과 섞인 문장을 함께 테스트한다. 정규식을 처음 접하는 팀원은 기대 결과를 문서로 먼저 작성하고 장우석과 검토한 뒤 패턴을 수정한다.

## 구현 한계

- 근거 확인은 정규식 기반이므로 의미 이해와 안전 보장을 대체하지 않는다. 복잡한 부정·간접화법·미등록 표현은 오판할 수 있다. 현재 패턴을 테스트 점수만으로 일반화하지 않는다.
- AI는 대사를 생성하지만 서버가 허용한 발언의 사실성까지 완벽히 보장하지는 않는다. 실제 AI 품질·인젝션 저항성 평가는 별도 필요하다.
- 세션·대화·리포트·호출 기록은 SQLite에 저장하고 재시작 후 이어갈 수 있다. 기관별 인증·다중 프로세스 동기화는 아직 미구현이다.
- 실시간 경과 시간을 평가하지 않는다. 횟수 소진을 실제 대피 속도 측정으로 표현하지 않는다.
- 11/25 Edge headless로 화재·지진 PC/모바일 완주·리포트·이미지·이어하기를 mock AI에서 검증했다. 실제 AI 전체 플레이와 교육 효과 검증은 별도이며 상세 결과는 실제AI_리허설.md를 따른다.

## 2026-11-25 구현 보강

- AI wrong 제안만으로 위험도를 올리지 않는다. 서버에 등록된 위험 표현이 확인될 때만 위험도를 높인다. 미등록 위험 행동의 누락은 추가 콘텐츠 검수 대상이다.
- 종료 리포트는 점수·상태를 서버가 확정한 뒤 AI에 평가 데이터만 전달한다. 인용 발언이 실제 평가 대상 발언과 일치하고 모든 평가 id가 반환됐는지 검증한다. 실패 시 기본 피드백을 사용하고 `feedback_source`로 구분한다. 결과는 DB에 캐시한다.
- 지진 시나리오와 장면 SVG 10개를 추가했다. SVG는 직접 작성한 개념도이며 공식 기관 이미지나 실제 현장 사진이 아니다. 자료 출처는 각 시나리오 sources에 기록한다.

행동 기준 확인에 참고한 원문: [행정안전부 화재 발생 시 요령](https://mois.go.kr/chd/sub/a06/fire/screen.do). 시스템이 실제 소방훈련이나 전문 검수를 대체한다고 주장하지 않는다.

## 대화 자유도 (2026-11-18 추가)

- 이용자는 상황 속 인물에게 자유롭게 묻고 말할 수 있다. AI는 매 턴 말의 종류(`intent`: action/question/chat)를 함께 제안한다.
- **판단 기회는 행동을 시도했을 때만 줄어든다.** 서버 기준: AI 판정이 correct/wrong 이거나, 행동 근거가 하나라도 확인되거나, 위험 패턴에 걸리거나, AI가 action 으로 분류한 경우. 그 밖의 질문·대화는 기회를 쓰지 않고 리포트의 판단 기록에도 넣지 않는다(대화 기록에는 남음).
- 질문·대화는 단계당 `MAX_FREE_TURNS_PER_STAGE`(6)회까지. 넘으면 이후 발언은 시도로 센다 (토큰 비용 보호).
- AI의 intent 는 기회를 **덜** 쓰게만 만들 수 있다. intent 가 없거나 이상하면 action 으로 본다. 진행·위험도·근거에는 영향이 없다.
- 시나리오 `role_doc.world_facts`(공통)와 단계별 `facts` 는 질문에 일관되게 답하기 위한 상황 정보다. 대피 방법·안전 수칙은 넣지 않는다 (정답은 rubric 이 담당).
- AI에게는 이번 단계의 확인된 행동/남은 행동, 지난 단계 결과(`story_so_far`)를 넘긴다. 일부만 맞았을 때 고정 문장 대신 상황에 맞게 재촉하게 하기 위함이며, 진행 결정에는 쓰지 않는다.
